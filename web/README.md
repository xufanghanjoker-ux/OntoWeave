# CQForge 单人本地工作台

> 本页记录此前 SQLite 工作台的实现。安装新版 PostgreSQL 工作台请使用[安装与启动指南](../docs/GETTING_STARTED.md)。

原生 HTML/CSS/JavaScript 前端与 Node.js 实验服务。使用根目录 package.json 锁定官方 Neo4j 驱动，不需要前端构建。只监听 `127.0.0.1`，不包含团队权限，不应转发到公网。

## 启动

```sh
npm ci
npm run setup
npm start
```

打开 `http://127.0.0.1:4317/`，在“模型设置”中连接兼容 Chat Completions 的模型。所有角色使用同一模型，但 Builder/Extractor 与 Evaluator 使用不同上下文；Evaluator 先独立读资料，再评审候选。

也可通过终端参数连接；密钥会在终端隐藏输入，不要放在启动参数或源码里：

```sh
node web/server.mjs --base-url https://your-model-endpoint.example --model your-model
```

非本机 HTTP 模型地址必须显式添加 `--allow-insecure-http`（界面也需要确认）。HTTP 会明文传输资料与认证头，不建议用于私有资料。重启服务需要重新输入密钥。

## 使用流程

1. 输入能力问题 CQ、已确认定义和可选查询日期。
2. 上传 PDF / DOCX / TXT / MD，先检查解析文字，再勾选本次发送与本地保存授权。
3. 构建任务依次进行本体生成、独立阅读、本体评审、抽取、声明复核，最多五次生成调用。
4. 查看“本体契约”，在“图谱探索”点选声明以查看原文、范围、量词、时间。
5. 在“CQ 查询”查看有限模板结果，缺证显示 UNKNOWN，不代表能力不存在；有争议项进入待处理，不自动执行修改建议。
6. 可导出任务 JSON，或“作为新版本修改”：补充定义/CQ/资料/时点，填写修订说明，保存本地草稿；勾选授权后完整重新验证。草稿可跨重启恢复，旧版本不覆盖。
7. 可选：在模型设置的折叠高级入口连接Neo4j。所有版本需主动同步；连接不自动同步新任务或切换查询后端。
8. 查询默认SQLITE，显式选择NEO4J才访问图数据库。构建快照不冒充查询结果。父子版本可查看定义、CQ、来源及答案差异。

结构化数据保存到 `local-runs/workbench/cqforge.sqlite`，原件与模型响应为不可变附件。旧JSON先备份后导入，原目录保留；新任务不双写task.json。业务资料与凭据不能提交开源仓库。

## 原型边界

- 最多 12 条 CQ、8 份资料；解析文字每份 6 万字符，总计 10 万字符。PDF/DOCX 每份不超过20MB，PDF不超过50页；不支持旧DOC。
- 查询支持 FACTS / ENTITIES / COMPARE / UNKNOWN 有限模板，不执行模型生成的 SQL/Cypher。COMPARE 逐主体返回同一属性的来源陈述，不排名；缺证主体为UNKNOWN。
- 关系浏览仍绘制本地版本快照；可选 Neo4j 持久化保留声明、证据、来源和版本路径。数据库使用 CQF 前缀标签，ID 按工作空间和版本隔离；不同版本实体不自动合并。
- SQLite为主存储，Neo4j为可选投影。显式NEO4J查询失败不静默回退；默认SQLite不受影响。同步失败不重跑模型。
- 接受候选不等于独立验证事实；来源默认“上传、原始发布者未确认”。
- 查询日期仅筛选有效起始时间，不能证明旧声明一直有效，也未实现自动时序消歧。
- ONE 属性仅对范围、单位、明确时间一致的互斥 EQ 值检测冲突；不等于完整冲突推理。
- 当前不自动修订、不提供人工审批写回或任意自然语言查询。服务重启会把未完成任务标为中断。
- 同模型的不同上下文有相关性风险，不等于独立权威审核。

## 离线测试

```sh
node --test web/engine.test.mjs web/server.test.mjs
```

API 测试仅监听临时本机端口并使用模拟模型，无外部模型调用。浏览器真实模型验收结果见 [验收记录](../docs/workbench-validation-20261013.md)。

可选真实数据库集成测试：`npm run test:neo4j`，隐藏输入数据库密码。仅写入独立工作空间的合成资料，不删除既有数据；生成与评审为明确标记的离线模拟，不是模型质量评测。详细说明见 [Neo4j 与修订闭环](../docs/neo4j-revisions-v1.md)。

界面布局参考 Utopia 的侧栏、中心图谱和证据侧栏思路，未复制其源码或素材。原型使用 Sites 技能的本地预览验收路径，不发布托管站点。

## Docling 环境

独立 Python 3.12 环境（模型权重与依赖许可需分别核对）：

```sh
python3.12 -m venv .venv-docling312
.venv-docling312/bin/python -m pip install -r web/requirements-docling.txt
```

标准入口为npm run setup，统一锁定依赖、下载和校验模型。缓存位于local-runs/docling-models；上传不隐式下载。网络受限时可在setup显式配置可信HF_ENDPOINT，不关闭HTTPS校验。解析worker不继承生成模型凭据。其他解释器路径可用CQFORGE_DOCLING_PYTHON指定。

## 引文校验与失败诊断

先逐字匹配；对 PDF/DOCX 的解析文本，仅允许移除汉字之间的排版空白后寻找唯一位置，并且必须落在同一解析块内。存入声明的仍是原文切片，保留模型原引文、源哈希、UTF16偏移与规则版本。数字、标点、英文词间空格、歧义和跨块拼接不做模糊放行。文本定位成功不代表语义得到支持，仍须复核。

无效声明逐条列入待处理问题，保留已定位候选，但整体事实查询关闭。技术错误记录失败阶段与已有产物。历史失败任务提供基于已存响应的离线复验，不自动重发模型调用、不改写历史状态，也不自动补成成功任务。
