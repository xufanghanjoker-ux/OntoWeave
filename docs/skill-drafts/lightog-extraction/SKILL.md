# 从资料发现领域知识

读懂当前正文，结合标题、定义、表格和前后句理解重要信息。CQ提示知识关注方向，问题族帮助共享关注点；保留成员差异。正文决定实际有哪些知识，未在问题中点名的对象和有用内容仍可发现。

先辨认资料中的实体、概念或类型及其含义，再寻找它们之间的联系。用有意义的名称表达关系两端，保留原文谓词、方向和限定。类型允许由资料带来；含义不明确时暂缺或分别保留，不根据同名强行合并。工作任务、处理模块或章节标题不能替代正文中真正的对象。

对象描述中的重要联系尽量另存为显式关系，说明谁与谁有什么联系、方向及限定。值先判断属于对象本身、对象间的关系，还是某次案例／观察；保留比较符、范围、单位、时间和条件，不把每个数字强制建成实体。公式、流程、约束和例外保留为规则，辨认适用对象或参与角色、触发条件、行为及例外；能明确的部分建立关联，其余保留完整规则正文，不补造角色。资料给出概念、关系或属性定义时一起保存，定义允许不完整，本体随知识增加而形成，不先编造一份完整schema。

例如，“设备A使用部件B”包含两个对象及使用关系；“设备A功率20W”可表达为属性；“温度超过阈值时降低功率”须保留温度条件。不能仅输出“设备降低功率”，也不把抽取任务当成设备的替身。这些只是合成示例，换领域仍使用同一方法。

再如，“订单甲由仓库乙发出，运输时效承诺为两天”：发出关系的承诺不能直接当成仓库固有属性。“某次配送耗时三天”是这次观察，不能据此写成所有订单的时效。“冷藏货物超温时隔离，检查合格可解除”应保留货物、超温条件、隔离行为及解除例外，不能缩成无条件隔离。这些合成例子只说明归属和条件，不预定领域类型或谓词。

尽量附支持陈述的原句或片段及可得资料选择。表格连同表头、单位和脚注理解；数字范围与公式保留实际端点和运算，不补未说明的下界或公式项。正文内部有条件冲突时保留两处信息和歧义；草案、规划、否定、预测及示例语气不能提升为已实施事实。

直接按本轮工具保存已经发现的对象、定义和知识，不必先列完主体、本体或任务。分批保存有用内容，结构暂不完整则保留文本和缺口；损坏或无用条目允许跳过，其余继续。精确引句无法定位时保留可确定来源和模型引句，不称为已核实原文，不为逐条质量反复补证或自评。

已提供完整窗口正文就复用它，缺少必要上下文时再定向阅读。先真实保存已发现内容，再申请结束，读取实际保存、结构化、文本保留、跳过及告警摘要。若Host提供一次局部回看机会并明确窗口尚未关闭，对照已有正文和已存知识找重要的结构残留：描述里的联系、尚未明确归属的值、规则可明确的对象或限定。线索本身不是错误，不按数量补边，不要求每个节点有边。

回看只提交有原文依据的增量，必要时引用回执中的简短知识标识说明补充哪一项；不重交整批、不改写或删除旧知识。需要详情时按简短标识读本窗口已存内容，不重复读整个知识库。没有增量可直接再次申请结束；以最终结束回执为准。Host未开启回看或预算不足时，按实际回执结束，不另开补全循环。程序维护阶段和预算，不必填写轮次、自评或执行统计。
