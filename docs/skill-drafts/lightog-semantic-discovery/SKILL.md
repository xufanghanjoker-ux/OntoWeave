# LightOG 语义识别

识别资料实际上说了什么，留下后续可回看、可组织的语义草稿。记录的是资料陈述，不因保存就成为已核实事实；此阶段无需决定最终图的节点、关系或属性种类。

## 理解原文

- 连同当前完整窗口的标题、段落、表头、行列和脚注理解正文。表头或上文提供的条件应随陈述保留；不要把相邻但无明确关联的段落拼成一件事。
- 识别对象、指代及参与角色。指代有明确依据时展开为可读称呼；可能指向多个对象时保留原称、候选与歧义，不凭同名或常识认定同一对象。
- 用自然语言说明谁做了什么、涉及谁或什么，以及角色之间的联系意图。区分委托、执行、接收、报告等角色，区分先后、相关与因果；多方事件可保留整体叙述，不急于拆成若干主客配对。
- 数字应连同归属对象或事件、比较符、单位、时间、范围及适用条件阅读。比例保留分子／分母或已说明的计算口径；“降低 20%”保留比较基准。原文未说明的归属或基准标明缺口，不自行补齐。表格空白或未测不改写为零。
- 保留否定、条件、例外及语气。区分已发生的案例、作者转述的主张、能力描述、建议、规划、假设与预测；不要把“可”“建议”“预计”写成已发生或必然发生，不把“未观察到”写成“不存在”。
- 已有 CQ／问题族只帮助判断阅读重点。正文出现的新对象、条件或有意义联系仍可记录；无需为每个 CQ 凑答案，也不在此阶段生成新的 CQ。

## 记录可审阅的语义陈述

每项围绕一个清楚陈述或紧密关联事件，用足够完整的自然语言表达；共享条件不可在拆分时丢失。避免只留下词语清单或只概括整段主题，也无需把原文逐句复制为独立条目。

保留以下实际可得内容即可，不要求补满统一表格或 JSON：

- **语义陈述**：资料表达的含义，包括必要的说话方、参与角色及限定。
- **原文片段**：支持理解的原句、连续片段或必要的多句及表头上下文。引文照录，不把改写伪装成原句；缺少可用定位时说明定位不足，不编造页码、引文或来源。
- **可选线索**：有助于后续组织的对象／角色、数值归属、条件，以及尚不能确定的指代、方向或含义。只写具体疑点，不用一个笼统置信分数替代。

区分“原文没有说明”与“当前窗口没有读到”。相互冲突的说法分别保留各自原文、说话方与适用范围，不代替资料裁定哪一个真实。必要时回看获准上下文以澄清局部含义；仍不能确定时保留不完整陈述和具体缺口，不用常识填平。

可以分批记录，保留各项原文依据，不只提交一份压缩摘要。后续知识组织需要的结构选择由下一阶段处理；无需填写最终主客 JSON、图类别、内部标识、版本、幂等信息或任务清单。

## 行动与后补记录

资料或短记录涉及做事经过时，保留当时对象与条件、判断依据、谁做了什么、执行进展及后来观察到什么。过程可以只有一部分；没有结果不妨碍记录一次建议、计划或失败尝试。

- 区分建议、计划、尝试、进行中、完成、部分完成和失败。到期的计划不自动完成；“尚未提交”也不是一次提交。通用操作说明不等于实际发生的实例。
- 分开阅读操作结果与业务效果。“工具返回成功”可能只说明步骤执行；未复测、无变化、失败、代价和副作用都应保留，不由操作完成推出目标达成。
- 观测保留对象、测量方法、窗口、条件、数值与单位；主观判断说明是谁的判断。“未达标”缺少标准时保留评价原话和标准缺口，不补判据。
- 沿程序提供的来源性质区分人工报告、Agent 自报、工具回执和文档转述。Agent 说“我完成了”可以记录为自报，不据此认证执行；文档写“工具成功”仍是文档转述，不伪造回执或文档引句。
- 后补内容只有明确回指、限定范围的事项编号或已核对对象时，才说明与先前过程的联系；同名、同编号不同站点、相邻段落或时间先后不足以认定同一过程。保留不同条件和具体歧义，不由先后变化写成因果。

业务时间保留原词与含义：“昨天”需要已有时间基准，“11 月”未必给出年份。未提供或无法解析时说明缺口，不按资料接收日补事件日期，也不填写系统接收、发布时间或版本信息。新反馈、更正旧说法与真实状态变化分别照原义表达，不自行覆盖旧记录。

## 可选的时间线索

在已有语义陈述旁，留下实际读到的时间原话，并说清它限定哪项陈述。可以用可选的 `temporal_hints` 记录 `time_text`、`statement`、`scope`、`quote` 和 `context_role`；没有线索就省略，不为补字段重读整份资料或阻塞原陈述保存。时间如何解析、程序标识及语义到知识的关联由后续程序维护，不填写 ID、偏移、版本或幂等键。

- 说明时间属于本句、某个表格行／列、章节还是整份文档；适用范围不清楚时留下歧义。表头、行名、脚注或限定提供依据时，把必要的原话一起保留，不能只摘日期而丢掉对象与条件。
- 保留被限定陈述的单位、条件、否定、计划／预测语气、观察者和本次观察的身份。量值里的“至少 8 小时”可能是运行时长，不等于陈述从何时起生效，也不据此生成生效区间。
- 文档发出日期、生效日期、统计截止、标题／命名期间和明确时区分开记录为候选。可分别用 PUBLICATION、EFFECTIVE、OBSERVATION、FISCAL_PERIOD、TIMEZONE 或 UNRESOLVED 表达所指；候选角色本身不证明它适用于所有陈述，也不在这里换算日期、时区或补年份。
- 不必先把陈述拆成最终知识结构。后续合并或拆分时仍需回看同一时间线索；现在只保留它限定的业务含义和原文，不给可能的每条知识统一盖日期。

原文定位不足时保留已有引句和具体告警，不编造精确坐标。时间缺失、作用范围不明或不同日期冲突只影响相应线索；原知识仍照可确认的含义保存。

## 合成正反例

以下例子只说明理解方法，不提供领域谓词表或固定输出模板。

**设备与条件、数值归属**

原文：“进气温度不高于 35℃ 时，X2 在连续模式下可运行至少 8 小时。节能模式尚未测试。”

合适：资料称，在进气温度 ≤35℃ 且使用连续模式的条件下，X2 可运行 ≥8 小时；资料另称节能模式尚未测试。两项均保留对应原句。

不合适：“X2 运行时长为 8 小时，节能模式为 0 小时。”这丢失条件与比较符，并把未测变成数值。

**物流与多方角色、指代**

原文：“启辰委托远航将样品送至云检。云检负责签收，凌温记录运输温度。其系统将在下月接入远航平台。”

合适：保留启辰为委托方、远航为受托运输方、云检为签收方、凌温为温度记录方的同一运输事件；另记资料计划下月进行系统接入，但“其系统”所指未能确定，保留原句待澄清。不能仅因“凌温”距离最近就认定系统归属。

不合适：“云检记录温度；凌温系统已接入远航。”这改换角色、强行消解指代，并把计划改成完成状态。

**研究与建议、否定、预测**

原文：“本研究在 12 名受试者中未观察到指标 A 的显著改善。作者建议延长随访，并预计扩大样本后可能观察到差异。”

合适：该研究在 12 名受试者的范围内未观察到指标 A 的显著改善；延长随访是作者建议，扩大样本后可能出现差异是作者预测。保留研究范围与原文语气，不由此判断干预是否有效。

不合适：“干预无效；延长随访和扩大样本会改善指标 A。”前者扩大了否定范围，后者把建议及不确定预测改成效果承诺。

**检修与后补反馈**

原文一：“检修单 42：计划明天更换泵密封。”原文二：“同一检修单：更换步骤成功，尚未复测。”原文三：“更换后 24 小时低负载复测，渗漏仍为 2 mL/h，噪声上升。”

合适：分别记录计划、报告的步骤完成、后补复测与副作用，保留同一检修单的回指及低负载条件；原文没有说明更换解决渗漏。不能改写为“更换密封有效”。

**馆藏记录与来源性质**

原文：“我已清洁馆藏 R8，感觉颜色更亮；无执行回执，光照条件不明。”程序标明来源为 Agent 报告。

合适：保留 Agent 自报清洁完成及其主观颜色判断，明确回执、测量和光照缺口。不能据这段报告标为系统直接观测，也不能与其他馆藏的相邻测量自动拼接。

## 运行边界

只使用本阶段提供的阅读与语义记录动作，处理获准窗口及允许回看的上下文；不外查真值、不回答 CQ、不调用图保存或知识组织动作。来源／窗口绑定、标识、阶段结算和预算由主程序管理，不在语义正文中另造流程。内容不足可留下部分陈述、空内容及具体缺口；失败或未知时保留已记录内容并停止，不自行重试或推进下一阶段。
