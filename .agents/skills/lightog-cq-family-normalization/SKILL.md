# 比较完整知识目标

根据实际问题、备注及必要来源区别，判断候选是否要求同一种可复用的完整回答。相似度仅用于找到候选，不能证明同族；不以减少族数为目标，也不推断事实正确或已有答案。

## 语义判断

- 比较对象之外的知识目标、操作和必答子目标。不同对象可有相同需求；同章、同关键词、同用公式或分类表，不足以证明同族。参数、步骤及条件共同构成一个完整计算或过程时，不机械拆碎。
- 替换对象、版本或日期后，代表问法仍须询问同一种目标。不能把不同属性、操作或输出藏进泛泛的“{对象}的规则”或用“计算或评分”拼接。若原题跨多个目标，保留原题并说明待明确，不用共同子目标代表整题。
- 保留否定范围、版本、规划语气、单位、例外及示例要求；必要差异用简短 notes 说明，原问题和特有备注由 Host 原样关联。代表问法不能把某成员的特有条件推广到全族，也不能静默删掉它。
- 时点状态、有效区间、变化历史与变更原因是不同目标。相同目标仅对象、日期或 as_of 不同时可保留参数差异；业务有效时点与当时已知资料的截止不能互换。来源不足不猜日期或因果。

## 本批材料与完成

Host 提供局部 CQ、候选已有族摘要及匹配成员时，只比较这些候选。已有族的摘要不足以判断完整目标或成员条件时，使用实际读取工具补看其成员；不遍历全部历史。沿用当前工具发放的题或族引用，不自造ID，不改写原问题。已有族引用表示保留其所有原成员，不表示只采用展示的匹配成员。

保存有依据的合族决定即可。无法确认或目标不同的候选可以不合并，Host 保留原题继续规划；不为了填满每题归属或消除告警再跑一轮。若宿主给的是整批清单，则提交其实际工具要求的归属／未归族内容。批次、映射、统计和后续推进由程序处理，不复述全部清单或哈希。

有保存工具时按实际 Schema 提交；无工具时返回一个 JSON 对象，含 families（name、representative_question、member_refs、可选 notes）与 unassigned（cq_ref、reason）。无编号时按输入顺序以 item:1 等位置引用。必要 notes 保持简短，不输出答案、评分或私有推理。交付成功即结束，不追加总结、审计或优化Agent。权限、失败及UNKNOWN停止规则不变。

## 正反例

- “甲／乙产品支持哪些部署方式？”可同族；“如何完成私有化部署？”另为操作过程。共同主题不能替代目标判断。
- “甲／乙承运商的运费按哪些参数和规则计算？”可同族，公式和分支不逐项拆族；“客服质量按什么标准评分？”不能因都涉及分数而并入运费计算。
- “甲站6月1日由谁值班？”与“乙站7月1日由谁值班？”可参数化；“值班安排何时有效？”、“值班人怎样变化？”、“为什么更换？”不能归为泛称的时间情况。认识截止与业务时点仍各自保留。
- 一题要求异常处理，另一同类题另要求案例：案例保留在对应成员及必要备注中，不因此要求全族补案例；若现有族还混含另一种操作，先读必要成员，不能只取其中相似的一段就合族。
